# Datenpaket Version 118

## Befehle

### Zusätzlich `compute`

-   Bewertungen `minecraft:number_provider` in verschiedenen Kontexten
-   In allen Kontexten `origin` wird auf die aktuelle Befehlskontextposition eingestellt, während `this` Unternehmen `@s`

Syntax:

-   `/compute [|integer]`, wo:
    -   \- einer von:
        -   `default` - führt Anbieter in `minecraft:command_compute_default` Kontext, wenn nur gemeinsame Argumente (Position und `this` Unternehmen sind verfügbar
        -   `block` \- führt Anbieter in `minecraft:command_compute_position` Kontext, in dem Blockzustand und Blockposition basierend auf Block an Position eingestellt werden
        -   `entity <entity selector>` - runs provider in `minecraft:command_compute_entity` context, where `target_entity` is set to selector result
    -   `<provider>` - either an element of `minecraft:number_provider` registry or inline value
    -   `<scale>` - optional scale value, defaults to `1.0`
        -   Final result will be multiplied by `<scale>` and rounded towards negative infinity
    -   `integer` - optional marker to use integer mode
        -   Due to truncation between intermediate steps this mode is not equivalent to float mode even if scale is `1.0`

### Änderungen an `data`

-   Neue Quelle hinzugefügt `/data modify ... append|insert|merge|prepend|set` genannt `compute`
-   Neue Quelle wird eine `minecraft:number_provider` und dann das Ergebnis entweder als Ganzes oder als Float-Tag bereitstellen
-   Syntax: `compute [integer]`, wo die Syntax `target`, `provider` und `integer` gleich wie in `/compute` Funktion
-   Beispiel: `/data modify storage foo bar set compute entity @n[type=minecraft:armor_stand] {type:score,target:{type:context,target:target_entity},score:baz}`

## Blocktransformatoren

-   Zusätzlich `minecraft:block_transformer` Registrierung mit Regeln zur Umwandlung eines Blocks in einen anderen Block
-   Format: Liste der Objekte mit Feldern:
    -   `block_state_provider` - Block State Provider, verwendet, um den Zustand für den transformierten Block
        -   Wenn der Block State Provider kein Ergebnis zurückgibt (wie von `rule_based_state_provider`, zum Beispiel), die nächste Regel in der Liste wird versucht
        -   Der Satz von Block State Providern sind die gleichen wie die Block State Provider in der Weltgeneration

-   `sound` - optionales Feld, Sound Event auf Interaktion, z. `minecraft:item.axe.strip`
    -   Wenn nicht vorhanden, spielt standardmäßig kein Sound Event
-   `particle` - optionales Feld, Partikel auf Interaktion zu spielen
    -   Wenn nicht vorhanden, Standardeinstellungen `none`
        -   `none`
        -   `scrape`
        -   `wax_on`
        -   `wax_off`
-   `disallowed_faces` - optionales Feld, Liste der Richtungen, welche Gesichter auf dem geklickten Block, die nicht mit
    -   Wird mit einem abgeschalteten Gesicht interagiert, wird die nächste Regel in der Liste versucht
    -   Wenn nicht vorhanden, wird eine leere Liste standardmäßig
    -   Werte:
        -   `up`
        -   `down`
        -   `north`
        -   `south`
        -   `east`
        -   `west`
-   `loot` - fakultative Loot-Tabelle, die Loot-Tabelle, um Elemente auf eine erfolgreiche Transformation, z. `minecraft:till/rooted_dirt`
    -   Wenn nicht vorhanden, verwendet standardmäßig keine Loot-Tabelle
-   `drop_strategy` - optionales Feld, konfiguriert aus, wo im Block jeder Loot fallen sollte
    -   Wenn nicht vorhanden, Standardeinstellungen `from_middle`
    -   Werte:
        -   `from_middle` - von der Mitte des Blocks
        -   `clicked_face` - aus dem Gesicht mit
-   `update_from_neighbors` - optional Boolean, wenn der transformierte Block auf Basis benachbarter Blöcke aktualisieren sollte. Dies ermöglicht z.B. Zäune zu verbinden
    -   Wenn nicht vorhanden, Standardeinstellungen zu true
-   `transform_type` - optionales Feld, konfiguriert, wie nahe gelegene Blöcke von der Transformation beeinflusst werden sollen
    -   Wenn nicht vorhanden, Standardeinstellungen `single_block`
    -   Werte:
        -   `single_block` - beeinflusst nur den mit
        -   `copper_chest` - wenn Eingangs- und Ausgangsblöcke beide Kupferkästen eines jeden bewitterenden Zustands sind, gewachst oder ungenutzt, wird diese Transformation beide Seiten einer doppelten Brust beeinflussen
-   `consume_on_use` - fakultativ Boolean, bestimmt, ob das Produkt verbraucht werden soll oder nicht
    -   Nur für stapelbare Gegenstände gilt
    -   Wenn nicht vorhanden, Standardeinstellungen `true`
-   `item_damage_per_use` - optional Integer, bestimmt, wie viel Schaden das Produkt mit jeder Verwendung nimmt
    -   Nur gilt für nicht stapelbare Gegenstände
    -   Wenn nicht vorhanden, Standardeinstellungen `0`
-   Standardwerte in Vanille:
    
    -   `minecraft:shovel` - Standardwert für Schaufeln
    -   `minecraft:axe` - Standardwert für Achsen
    -   `minecraft:hoe` - Standardwert für Hoes

    ### Materialregeln
    
    #### Zusätzlich `minecraft:ore_vein`
    
    -   Format: Objekt mit Feldern:
        -   `ore_block` - Blockstaat, der Erzblock zu platzieren
        -   `raw_ore_block` - Blockstaat, der Roherzblock zu platzieren
        -   `filler_block` - Block-Zustand, der Einfüllblock zu platzieren
        -   `raw_ore_chance` - schweben zwischen 0 und 1, die Wahrscheinlichkeit für eine `raw_ore_block` anstatt eines `ore_block`
        -   `density` - Dichte Funktion, die Wahrscheinlichkeit zwischen 0 und 1 für den Erzgang, um einen Block zu ersetzen
            -   wenn `0` oder darunter, kein Block wird ersetzt
        -   `richness` - Dichte-Funktion, die Wahrscheinlichkeit zwischen 0 und 1 für `ore_block` oder `raw_ore_block` zu platzieren (im Gegensatz zu `filler_block`)
            -   wenn `0` oder niedriger, alle Blöcke werden `filler_block`
            -   wenn `1` oder größer, keine Blöcke werden `filler_block`
        -   `filler_gap` - Dichte-Funktion, wirkt als Überschreitung `richness`: wenn positiv, `filler_block` wird immer platziert
    
    #### Geändert `minecraft:noise`
    
    Folgende Felder wurden eingeführt:
    
    -   `shift_x` - optionale Density-Funktion, eine Domain-Warp auf x
        -   Wenn nicht angegeben, wird keine Verwarnung angewendet (entsprechend `0`)
    -   `shift_y` - optionale Density-Funktion, eine Domain-Warp auf y
        -   Wenn nicht angegeben, wird keine Verwarnung angewendet (entsprechend `0`)
    -   `shift_z` - optionale Density-Funktion, eine Domain-Warp auf z
        -   Wenn nicht angegeben, wird keine Verwarnung angewendet (entsprechend `0`)

    -   Ersetzt von `minecraft:noise`

    -   `cell_size_y` - positiver Int, Größe in Blöcken der Interpolationsgitterzellen auf der Y-Achse
