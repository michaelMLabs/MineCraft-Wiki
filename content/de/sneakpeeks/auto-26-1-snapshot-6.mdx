Vorsicht! Ein Paket von sieben flockigen und fruchtigen Baby-Mobs haben den Snapshot übernommen! Diese winzigen Füchse, Eisbären, Bienen, Ilamas, Armadillos und Ziegen könnten schmackhaft neues Aussehen haben, aber vielleicht nicht alle kuschelig (oder tamabel!). Von der eisigen Tundra bis zu den sandigen Wüsten – wenige Biome sind vor ihrer Süße sicher!

Und auf der technischen Front: Die Veröffentlichung dieser Woche bringt einige wichtige Änderungen im Weltdatenformat mit sich, so stellen Sie sicher, dass Sie das vollständige Changelog unten lesen, bevor Sie Ihre Welten aktualisieren.

Glücklicher Bergbau!

# Änderungen

-   Überarbeitet die Visualisierungen von mehr Baby-Mobs
-   Baby Polar Bären greifen keine Foxes mehr an
-   Baby Axolotls haben jetzt ein Spiel tote Animation
-   Die Flügel des Baby-Hühners und die Streifen des warmen Huhns fixiert

## Baby Mobs

-   Aktualisiert die Modelle und Texturen der folgenden Babymobs:
    -   Bienen
    -   Fuchs
    -   Ziegen
    -   Kamel
    -   Armadillo
    -   Polarbär
    -   Llama
-   Sattel auf Baby Camels wird nicht mehr
-   Camel Husk hat kein Babymodell mehr

## UI

-   Zusammen mit großen Änderungen des Weltdatenformats in dieser Veröffentlichung werden jetzt Welten angezeigt, die aktualisiert werden müssen `Upgrade and Play` anstatt `Play Selected World` und `Edit World` und `Re-Create World` Tasten werden deaktiviert, bis die Welt aktualisiert wurde
    -   Ein neuer Bildschirm wurde hinzugefügt, um den Fortschritt zu verbessern

> **Anmerkung des Entwicklers**: _Aufgrund des zusätzlichen Risikos beim Upgrade einer Welt werden wir ein Backup zwingen, wenn Sie Ihre Welt zum ersten Mal in diesem Snapshot-Zyklus laden. Nach dem Upgrade können Sie Ihre Welt nicht in einer älteren Version laden._

# Datenpaket Version 99

## Weltlager

-   Alle Standardabmessungen werden nun in der `dimensions` Unterordner
    -   Daten für die Überwelt wurden vom Wurzelordner in `dimensions/minecraft/overworld`
        -   Dies umfasst `region`, `entities`, und `poi` Ordner, sowie verwandte Dateien aus `data`
    -   Daten für den Nether wurden von `DIM-1` bis `dimensions/minecraft/the_nether`
    -   Daten für das Ende wurden von `DIM1` bis `dimensions/minecraft/the_end`
    -   Die obere Ebene `data` Ordner ist jetzt nur für Daten, die über Dimensionen geteilt werden, anstatt auch für die Überwelt
-   Spieler-Speicher wurde in die `players` Unterverzeichnis
    -   `advancements` -> `players/advancements`
    -   `playerdata` -> `players/data`
    -   `stats` -> `players/stats`
-   Das Weltressourcenpaket (`resources.zip`) in die `resourcepacks` Unterverzeichnis
-   Daten, die im `data` Ordner ist jetzt namespaced
    -   Dies bedeutet, dass alle Daten nun in einem Namenspace-Unterordner im entsprechenden `data` Ordner
        -   Alle vorhandenen Vanille-Datendateien wurden entsprechend verschoben
        -   Beispiel: `data/scoreboard.dat` -> `data/minecraft/scoreboard.dat`
    -   Befehlsspeicher wird nun in Namenspace-Unterordner gespeichert, anstatt einen Namenspace-Suffix zu haben
        -   Beispiel: `data/command_storage_foo.dat` -> `data/foo/command_storage.dat`

-   `chunks.dat` wurde umbenannt `chunk_tickets.dat`
-   Daten für Karten werden nun in der `data/minecraft/maps` Unterordner
    -   Kartenindex-Dateien wurden nur auf die Zahl umbenannt
        -   Beispiel: `map_1.dat` -> `1.dat`
    -   `idcounts.dat` wurde umbenannt `last_id.dat`
-   Es gibt nicht mehr `raids_end.dat` Sonderfall
    -   Das Ende verwendet jetzt `raids.dat` und
-   Die durch Strukturblöcke gespeicherten Strukturen wurden aus `generated/namespace/structures` bis `generated/namespace/structure`

    ## Weltgeneration
    
    -   Regelbasierte Block-Zustandsanbieter haben sich so geändert, dass ihre `fallback` ist optional und kann leer sein
        -   In solchen Fällen, dass ein leerer Rückfall aufgerufen wird, Funktionen, die sie verwenden, wird nichts
        -   Aktuelle Konfiguration, die einen regelbasierten Block-Zustandsanbieter verwendet, ist die `state_provider` in der `disk` Funktion
    -   `forest_rock` Funktion wurde umbenannt `block_blob`
    -   `block_blob` die Funktion Konfiguration hat sich geändert, um die folgenden Parameter zu unterstützen:
        -   `state` Der Stein ist aus
        -   `can_place_on` Ein Block-Prädikat, das definiert, welche Blöcke das Gestein aufgesetzt werden kann
    -   `ice_spike` Funktion wurde umbenannt `spike`
    -   `spike` Funktion Konfiguration unterstützt nun die folgenden Parameter:
        -   `state` Der Block, den die Spitze aus
        -   `can_place_on` Ein Block-Prädikat, das definiert, welche Blöcke der Dorn aufgesetzt werden kann
        -   `can_replace` Ein Block-Prädikat, das definiert, welche Blöcke der Dorn ersetzen kann
    -   `huge_red_mushroom` und `huge_brown_mushroom` Feature-Konfigurationen haben einen neuen Parameter:
        -   `can_place_on` Ein Block-Prädikat, das definiert, welche Blöcke der riesige Pilz aufgesetzt werden kann
    -   `alter_ground` die Konfiguration des Baumdekorators geändert hat, so dass `provider` ist nun ein regelbasierter Block-Zustandsanbieter
    -   `tree` Funktion Konfiguration ersetzt die `force_dirt` und `dirt_provider` Parameter mit einem einzigen `below_trunk_provider` regelbasierter Block-Zustandsanbieter:
        -   Format:
            -   `fallback` - Ein optionaler Block-Staatsanbieter
            -   `rules` - Eine Liste der Regeln
                -   `if_true` - Ein Block-Prädikat, der die Blockposition überprüft, bevor der Block
                -   `then` - Ein Block-Staatsanbieter
-   Standardwert:
    
    ```
    "below_trunk_provider": {
        "rules": [
            {
                "if_true": {
                    "type": "minecraft:not",
                    "predicate": {
                        "type": "minecraft:matching_block_tag",
                        "tag": "minecraft:cannot_replace_below_tree_trunk"
                    }
                },
                "then": {
                    "type": "minecraft:simple_state_provider",
                    "state": {
                        "Name": "minecraft:dirt"
                    }
                }
            }
        ]
    }
    ```
    
-   Bäume, die zuvor verwendet wurden `force_dirt` eine `below_trunk_provider` dass immer `dirt` stattdessen

    ## Schlagwörter
    
    ### Block Tags
    
    -   Split auseinander `#dirt` in mehrere Block-Tags
        -   `#dirt` jetzt nur enthält Dirt, Coarse Dirt und Rooted Dirt
        -   `#mud` enthält Mud und Muddy Mangrove Roots
        -   `#moss_blocks` enthält Moss Block und Pale Moss Block
        -   `#grass_blocks` enthält Grass Block, Mycelium und Podzol
    -   Zusätzlich `#substrate_overworld` enthält `#dirt`, `#mud`, `#moss_blocks` und `#grass_blocks`
        -   Dies wird als Sammlung für Weltgenerierungsbedingungen verwendet
    -   Hinzugefügt die folgenden Tags, die definieren, welche Bodensteine unter einem anwendbaren Baum oder Bambus durch podzol ersetzt werden können:
        -   `#beneath_tree_podzol_replaceable`
        -   `#beneath_bamboo_podzol_replaceable`
    -   Zusätzlich `#cannot_replace_below_tree_trunk` enthält `#dirt`, `#mud`, `#moss_blocks` und `podzol`
    -   Hinzugefügt die folgenden Tags, die definieren, welche blockieren ihre Funktion auf
        -   `#forest_rock_can_place_on`
        -   `#huge_brown_mushroom_can_place_on`
        -   `#huge_red_mushroom_can_place_on`
    -   Zusätzlich `#ice_spike_replaceable` definieren, welche Blöcke eine Ice Spike Funktion ersetzen kann
    
    ### Artikel Tags
    
    -   Hinzugefügt die folgenden Tags, die ihre Block-Tag-Inhalte spiegeln:
        -   `#mud`
