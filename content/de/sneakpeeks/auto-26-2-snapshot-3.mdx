Wir sind wieder mit einem dritten Snapshot für 26.2, heute bringen wir Ihnen Schwefelspitzen zu testen! Diese scharfen Blöcke wachsen in Schwefelhöhlen, Hinzufügen eines bunten, sinnlichen Touch zu Ihren Builds! Aber Vorsicht - fallende Schwefelspitzen sicher packen eine Punktur!

Happy Mining!

# Neue Features

## Schwefel

-   Ist ein neuer Block, der natürlich auf Schwefelblöcke innerhalb der Schwefelhöhlen Biome erzeugt
-   Formt ein Stalaktit, wenn auf die Decke oder ein Stalagmit auf dem Boden platziert
-   Kann zu längeren Stalaktiten und Stalagmiten kombiniert werden
-   Stalaktiten und Stalagmiten verschmelzen, wenn die Spitzen nebeneinander liegen, es sei denn, Sie drücken Verschiebung während der Platzierung
-   Stalagmites wird brechen, wenn sie nicht an etwas darunter hängen
-   Stalaktiten fallen herunter, wenn nicht an etwas über
-   Von einem fallenden Stalactit getroffen zu werden schmerzt, und sie sind scharf!
-   Werfen Tridents brechen Schwefel Spike

## Prädikate

### Entity Predicates

Entity Predicate Format hat sich von einer Struktur mit mehreren optionalen Feldern auf eine ähnlich wie Datenkomponenten-Karten geändert.

Zum Beispiel, zuvor `effects` war ein optionales Feld:

```
{
    "effects": {...}
}
```

In dieser Version ist es ein komponentenähnlicher Sub-Prädikat-Eintrag geworden:

```
{
    "minecraft:effects": {...}
}
```

Die wichtigsten Funktionsänderungen sind:

-   Alle Schlüssel in Entity-Prädikaten sind jetzt Kennungen
    -   Da Kennungen ohne Namespace geschrieben werden können (Standard an `minecraft` Namespace), bestehende Feldnamen sind noch gültig
    -   Ausnahme: Feld `type` wurde umbenannt `minecraft:entity_type`
-   Unbekannte Subprädikatkomponenten werden nun zurückgewiesen (bisher unbekannte Felder wurden ignoriert)

Vorhandene typspezifische Sub-Prädikate wurden umbenannt und auf Top-Level verschoben.

-   `minecraft:lightning` bis `minecraft:type_specific/lightning`
-   `minecraft:fishing_hook` bis `minecraft:type_specific/fishing_hook`
-   `minecraft:player` bis `minecraft:type_specific/player`
-   `minecraft:raider` bis `minecraft:type_specific/raider`
-   `minecraft:sheep` bis `minecraft:type_specific/sheep`
-   `minecraft:slime` bis `minecraft:cube_mob` wie es jetzt enthält Sulfur Cubes zusätzlich zu Slimes und Magma Cubes

Zum Beispiel:

```
{
  "type_specific": {
    "type": "minecraft:player",
    "looking_at": {
      "type": "minecraft:ender_dragon"
    }
  }
}
```

wird

```
{
  "minecraft:type_specific/player": {
    "looking_at": {
      "minecraft:type": "minecraft:ender_dragon"
    }
  }
}
```

#### Zusätzlich `minecraft:entity_tags` Unterauftragnehmer

Dieses Prädikat entspricht Entity-Tags (d.h. mit dem `/tag` Befehl).

Felder:

-   `any_of` - optionale Liste von Strings, wenn vorhanden, muss die angepasste Einheit mindestens eines der aufgelisteten Tags haben
-   `all_of` - optionale Liste von Strings, falls vorhanden, muss die angepasste Einheit alle aufgelisteten Tags haben
-   `none_of` - optionale Liste von Strings, wenn vorhanden, muss das angepasste Unternehmen keine der aufgeführten Tags haben

## Weltgeneration

### Overworld Features

-   Einstellbarer Funktionstyp `lake`
    -   Zusätzliches Feld `can_place_feature` - Block Predicate, beschreibt, welche Blöcke diese Funktion platziert werden kann
    -   Zusätzliches Feld `can_replace_with_air_or_fluid` - Block Predicate beschreibt, welche Blöcke dieses Feature durch Luft oder die bereitgestellten ersetzen kann `fluid` Block
    -   Zusätzliches Feld `can_replace_with_barrier` - Block Predicate beschreibt, welche Blöcke diese Funktion ersetzen kann mit der bereitgestellten `barrier` Block
